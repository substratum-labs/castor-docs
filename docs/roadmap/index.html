Roadmap

Phase 1: Python Prototype (Complete)​

All core PRD requirements are implemented with 249 passing tests.

MilestoneStatusFeatures
M1: Core KernelCompleteDam (tool registry), Capability Manager, tool validation, self-correction feedback
M2: SchedulerCompleteSyscallProxy 9-step pipeline, checkpoint/replay, HITL approve/reject/modify
M3: MemoryCompleteLodge (context window MMU), FIFO eviction, pinning, semantic page-in
M4: Multi-AgentCompleteSync spawn, async spawn/join, CLI, child HITL propagation
M5: StreamingCompleteStreamingLLMSyscall, token-level preemption, partial_work capture, proportional budget

Additional:

  • V2 API — Castor facade class with sensible defaults, HITL policies, structured results
  • Guard Layer Demos — smolagents (L1 + L2) and pydantic-ai (L1 + L2) integration examples

Phase 2: Rust Performance Core (Planned)​

Push the hot paths to a memory-safe, system-level language via PyO3.

ComponentPriorityRationale
CapabilityManagerHighHot path — deduction on every syscall
Dam validationHighPydantic model building is CPU-bound
Replay engineMediumLinear scan of syscall log
Checkpoint serializationMediumJSON serialization overhead

Delivery format: Upper-layer developers still use import castor in Python. The Rust core is a compiled extension module via Maturin.

Future Directions​

Constellation (Distributed Orchestration)​

Scale from single-process to distributed agent orchestration:

  • AgentCheckpoint as the portable unit of execution
  • Agent Runtime Interface (ARI) for cross-node communication
  • Distributed budget tracking with consensus

Production Readiness​

  • Real SemanticMemoryDriver with vector search (Qdrant, Pinecone, or local embeddings)
  • OpenTelemetry observability — structured spans per syscall, trace propagation through child agents
  • Crash recovery strategy — write-ahead logging or idempotency documentation
  • Tool execution timeouts — ProcessPoolExecutor for CPU-bound tools

Formal Verification​

  • Budget conservation invariant (delegate + reclaim is closed)
  • HITL safety (no destructive tool executes without approval)
  • Replay determinism (same log produces same trace)
