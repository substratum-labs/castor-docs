Checkpoint / Replay

Castor's execution model is based on checkpoint/replay — not coroutine serialization. This document explains why, how it works, and what guarantees it provides.

The Problem​

Castor needs to suspend agent execution (for HITL approval, preemption, or resource limits) and resume later — potentially hours or days later, possibly in a different process.

The original design proposed "serializing the coroutine state." This is impossible in Python. asyncio coroutines hold:

  • C-level stack frames (not accessible from Python)
  • References to the event loop (process-specific)
  • Closures over mutable state
  • File handles, network connections, and other non-serializable resources

You cannot pickle.dumps() a live coroutine.

Two Approaches Analyzed​

Approach A: Explicit State Machine (Rejected)​

Convert every agent function into a state machine with serializable state:

class AgentPhase(str, Enum):
    SEARCH = "search"
    ANALYZE = "analyze"
    DONE = "done"

class AgentState(BaseModel):
    phase: AgentPhase = AgentPhase.SEARCH
    search_results: list | None = None

async def research_agent(state: AgentState, kernel):
    if state.phase == AgentPhase.SEARCH:
        state.search_results = await kernel.execute("web_search", {"q": "topic"})
        state.phase = AgentPhase.ANALYZE
        return state
    if state.phase == AgentPhase.ANALYZE:
        # ... more phases

Problems:

  • Extremely verbose — every agent becomes a state machine
  • Scales poorly — 10 tool calls means 10+ phases; conditionals cause phase explosion
  • Unnatural — agent logic is spread across phases instead of reading top-to-bottom
  • Couples agent to kernel — the agent must know it's running in a suspend/resume system

Approach B: Checkpoint at Syscall Boundary (Chosen)​

Agent functions are plain async def functions. The kernel records a log of completed syscalls. On resume, it replays the function from the top, serving cached responses.

async def research_agent(proxy: SyscallProxy) -> str:
    results = await proxy.syscall("web_search", query="topic")
    analysis = await proxy.syscall("llm_call", prompt=f"analyze {results}")
    await proxy.syscall("send_email", body=analysis)
    return "done"

The agent reads naturally — top to bottom, no phases, no state management.

How Replay Works​

The SyscallProxy maintains a replay cursor (_replay_index) into the checkpoint's syscall_log:

class SyscallProxy:
    async def syscall(self, tool_name, arguments):
        request = {"tool_name": tool_name, "arguments": arguments}

        # Replay: return cached response
        if self._replay_index < len(self.checkpoint.syscall_log):
            record = self.checkpoint.syscall_log[self._replay_index]
            assert record.request == request  # determinism check
            self._replay_index += 1
            return record.response

        # New syscall: validate, check HITL, execute or suspend
        ...

Suspend/Resume Flow​

First run:
  syscall("web_search", ...)     -> executes, logs result, returns
  syscall("llm_call", ...)       -> executes, logs result, returns
  syscall("send_email", ...)     -> destructive! raises SuspendInterrupt
  |
  Coroutine destroyed. Checkpoint saved: syscall_log = [web_search, llm_call]

Resume (after human approval):
  syscall("web_search", ...)     -> replay_index=0, return cached result
  syscall("llm_call", ...)       -> replay_index=1, return cached result
  syscall("send_email", ...)     -> replay_index=2, past cache -> execute live
  |
  Agent completes normally

The agent function runs twice, but the first two syscalls are served from cache — instant, deterministic, no side effects.

Determinism Guarantee​

The key insight: LLM agent functions are naturally deterministic between syscalls. Given the same tool responses, the agent makes the same decisions, because the LLM calls are themselves syscalls captured in the log.

The proxy verifies this with an assertion: on replay, if the agent issues a different syscall than what's in the log, a ReplayDivergenceError is raised. This detects corruption or non-deterministic agent code.

What Breaks Determinism?​

  • Random side effects between syscalls — random.random() to decide which tool to call. In practice, rare for LLM agents.
  • External state reads between syscalls — reading a file directly (bypassing proxy.syscall()). All external interactions must go through the proxy.

Special Cases​

HITL Modification​

When a human modifies a pending HITL request, the original request is logged as HITL_MODIFIED with feedback. The kernel never mutates the agent's arguments — this would break replay. Instead, the LLM re-plans using the feedback.

Kernel Tools​

Some tools are kernel-internal (e.g., sys_kernel_page_out for MMU eviction). These are auto-skipped during replay because their side effects are baked into the checkpoint state.

Child Agents​

spawn_agent is just another syscall. The child's entire execution (its own AgentCheckpoint with its own syscall_log) becomes the response of the parent's spawn syscall. On parent replay, the child is not re-run — its result is served from the parent's cache.

Trade-offs​

Replay Cost​

On resume, the agent re-executes from the top. Cached syscalls return instantly, but pure computation between syscalls is re-executed. For typical LLM agents, this is trivial (JSON parsing, string formatting) — milliseconds per replay.

Log Growth​

The syscall log grows linearly with the number of tool calls. For agents with hundreds of syscalls, this is still manageable (each record is a small JSON object). Long-running agents may benefit from log compaction (not yet implemented).
